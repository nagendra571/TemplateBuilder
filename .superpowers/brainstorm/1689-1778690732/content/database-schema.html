Database Schema

Two core tables — Templates (metadata) and TemplateVersions (body history)

📋 Templates
Column Type Notes
Id INT PK, identity
Name NVARCHAR(200) required, unique
TemplateType NVARCHAR(50) Email, Report, Notice, Custom
Description NVARCHAR(500) nullable
CurrentVersionId INT FK → TemplateVersions
IsActive BIT soft delete / disable
CreatedAt DATETIME2
UpdatedAt DATETIME2
🗂 TemplateVersions
Column Type Notes
Id INT PK, identity
TemplateId INT FK → Templates.Id
VersionNumber INT 1, 2, 3… per template
Body NVARCHAR(MAX) HTML + Scriban syntax
ChangeComment NVARCHAR(500) optional save note
CreatedAt DATETIME2
CreatedBy NVARCHAR(100) nullable for v1 (no auth)
Relationship & Key Design Decisions
Templates
1 ──── N
TemplateVersions
Templates
N ──── 1
CurrentVersion

The CurrentVersionId pointer means the NuGet only needs one fast lookup — no MAX(VersionNumber) query at runtime.

No SQL View metadata stored
Views are auto-discovered live from the DB at design time. Nothing to keep in sync.
Soft delete via IsActive
Deactivated templates are hidden from the designer list but still renderable by ID (existing callers don't break).
EF Core migrations
Schema managed via code-first EF Core. One migration to set up, easy to extend.
